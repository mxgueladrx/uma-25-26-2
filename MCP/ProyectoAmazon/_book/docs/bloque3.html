3.1.2 Definición de Categorías Artificiales

Ante la ausencia del atributo de “Categoría” en el dataset original, utilizaremos las estructuras comunitarias descubiertas por el algoritmo de Louvain en el Bloque 2 como categorías artificiales del mercado.

A la falta de conocimiento sobre el apartado, la IA me recomendó aplicar la siguiente estrategia para la clasificación de categorías: mantenemos las 3 grandes comunidades mayoritarias bien identificadas y agrupamos el resto bajo la etiqueta global de Nicho_minoritario.

3.1.3 Clasificación por Roles Estructurales

Para clasificar los productos según su posición en el grafo, transformamos las métricas de PageRank y Betweenness en perfiles lógicos de negocio.

Establecemos el corte en el percentil 90 (top 10%) de cada métrica para aislar a los productos más influyentes. Seguiremos una estructura para clasificar los artículos en cuatro roles:

  • Titán: Productos en el top 10% de ambas métricas. Presentan una influencia masiva y actúan como puentes principales del mercado.
  • Líder: Productos en el top 10% de PageRank. Actúan como faros en sus respectivas categorías.
  • Conector: Productos en el top 10% de Betweenness. Se encargan de unir distintas categorías.
  • Periférico: Productos que no destacan en general.
umbral_pagerank <- grafo |>
  activate(nodes) |>
  as_tibble() |>
  pull(PageRank) |>
  quantile(0.90)

umbral_betweenness <- grafo |>
  activate(nodes) |>
  as_tibble() |>
  pull(Betweenness) |>
  quantile(0.90)

grafo <- grafo |>
  activate(nodes) |>
  mutate(Rol = case_when(
    PageRank >= umbral_pagerank & Betweenness >= umbral_betweenness ~ "Titán",
    PageRank >= umbral_pagerank ~ "Líder",
    Betweenness >= umbral_betweenness ~ "Conector",
    .default = "Periférico"
  ))

3.1.4 Predicción por Homofilia

El proceso que llevaremos a cabo consiste en predecir la categoría de un producto a partir de sus vecinos, teniendo en cuenta además el peso de las conexiones. Por ejemplo, si un producto está conectado con 3 productos de categoría X y también con 3 de categoría Y, desempatamos por la suma de los pesos de cada categoría.

El pipeline es el siguiente:

nodos <- grafo |> 
  activate(nodes) |> 
  as_tibble() |> 
  mutate(id_nodo = row_number()) # Posición original de cada producto

aristas <- grafo |> 
  activate(edges) |> 
  as_tibble()

# Como el grafo no es dirigido, un enlace conecta de from a to y viceversa.
# Duplicamos las filas invirtiendo los ejes para obtener todos los vecinos de cada producto.
aristas_bidireccionales <- bind_rows(
  aristas |> select(nodo_origen = from, nodo_destino = to, weight),
  aristas |> select(nodo_origen = to, nodo_destino = from, weight)
)

# Obtenemos la categoría de cada nodo destino (vecino)
aristas_con_categoria <- aristas_bidireccionales |>
  inner_join(
    nodos |> select(id_nodo, CategoriaVecino = Categoria),
    by = c("nodo_destino" = "id_nodo")
  )

# Agrupamos por producto origen y sumamos los pesos de sus vecinos
votacion_ponderada <- aristas_con_categoria |>
  group_by(nodo_origen, CategoriaVecino) |>
  summarise(PuntosTotales = sum(weight), .groups = "drop")

# Para cada producto, nos quedamos solo con la categoría más votada
predicciones_finales <- votacion_ponderada |>
  group_by(nodo_origen) |>
  # slice_max selecciona la fila con el máximo de puntos. 
  # Si hubiera un empate, with_ties = FALSE elige uno para no duplicar filas.
  slice_max(order_by = PuntosTotales, n = 1, with_ties = FALSE) |>
  ungroup() |>
  select(id_nodo = nodo_origen, PrediccionHomofilia = CategoriaVecino)

# Unimos las predicciones con nuestra lista de nodos original
nodos_actualizado <- nodos |>
  left_join(predicciones_finales, by = "id_nodo") |>
  # Si algún producto hubiera quedado sin vecinos, le ponemos una etiqueta
  mutate(PrediccionHomofilia = if_else(is.na(PrediccionHomofilia), "sin_vecinos", PrediccionHomofilia)) |>
  arrange(id_nodo)

# Inyectamos la nueva columna de predicción
grafo <- grafo |>
  activate(nodes) |>
  mutate(PrediccionHomofilia = nodos_actualizado$PrediccionHomofilia)

Evaluamos el modelo con la construcción de una matriz de confusión y el cálculo del accuracy:

Obtenemos un accuracy casi perfecto, un 99.91%. Todo esto se debe a lo siguiente:

  • Modularidad: Como estudiamos en el Bloque 2, obtuvimos un 0.722 de modularidad con el algoritmo de Louvain. Un valor tan alto demuestra que el mercado está fragmentado en comunidades muy cerradas y determinadas. Las conexiones se concentran en el interior de cada comunidad y apenas existen aristas que crucen hacia el exterior. Al aplicar la homofilia, la mayoría de los vecinos de un producto pertenecen a su mismo grupo por la estructura de las comunidades.
  • Fallos: El modelo ha cometido 4 fallos.
    • Conectores: Tres de los errores corresponden a productos con el rol de Conector. Al ser nodos con un alto betweenness, están situados en la frontera que divide a dos comunidades. Sus vecinos se encuentran repartidos entre ambos grupos, lo que provoca que la votación se complique.
    • Periférico: El único producto Periférico que ha fallado presenta un betweenness de 0 y pertenece a una comunidad aislada que tiene solo 3 vecinos. Al contar con una vecindad tan reducida, cualquier interacción con un producto de fuera tiene el poder de cambiarle la categoría, ya que no hay suficientes vecinos dentro para ganarle la votación.

3.1.5 Identificación del Usuario “Élite”

Planteemos la idea de que un usuario es tan importante para como lo sean los productos que consume.

Vamos a caracterizar a cada usuario calculando el PageRankMedio de su cesta de la compra. Establecemos como usuario élite a aquellos situados en el top 10% superior de esta métrica.

# Nos quedamos con el producto y su pagerank
productos_pagerank <- grafo |>
  activate(nodes) |>
  as_tibble() |>
  select(name, PageRank)

# Mapeamos el pagerank al df original por usuario
usuarios <- df |>
  select(UserId, ProductId) |>
  inner_join(productos_pagerank, by = c("ProductId" = "name")) |>
  group_by(UserId) |>
  summarise(
    PageRankMedio = mean(PageRank),
    TotalResenas  = n(),
    .groups = "drop"
  )

# Umbral de corte top 10%
elite <- quantile(usuarios$PageRankMedio, 0.90)

usuarios <- usuarios |>
  mutate(TipoUsuario = ifelse(
    PageRankMedio >= elite, 
    "Usuario_Élite", 
    "Usuario_Estándar"
  ))

resumen <- usuarios |>
  count(TipoUsuario, name = "CantidadUsuarios") |>
  mutate(Porcentaje = (CantidadUsuarios / sum(CantidadUsuarios)) * 100)

resumen
# A tibble: 2 × 3
  TipoUsuario      CantidadUsuarios Porcentaje
  <chr>                       <int>      <dbl>
1 Usuario_Estándar            59953       89.9
2 Usuario_Élite                6765       10.1

Podemos ver que el mercado se divide en dos perfiles:

  • Usuarios Élite (top 10%): Detectamos a los usuarios élite por la importancia de lo que compran. Son usuarios cuyos comentarios se concentran en los “Titanes” y “Líderes” de la red. Son los creadores de tendencias de Amazon: si ellos compran algo, es porque es un producto clave que mueve el mercado.
  • Usuarios Estándar (90% restante): Es el consumidor base y común de la plataforma. Sus reseñas y compras se dispersan de forma totalmente aleatoria por productos periféricos o pequeños nichos minoritarios. Compran lo que necesitan en el día a día, por lo que su impacto individual a la hora de mover las tendencias de la red es casi nulo.

Como has pedido explícitamente el código para desencallar este paso, aquí tienes la sintaxis exacta, limpia y comentada para tu documento Quarto. Este bloque utiliza exactamente tus variables (grafo) y la lógica de unir y agrupar dataframes que ya dominas.

# ==============================================================================
# Paso 3: Reto de Predicción por Homofilia Ponderada (Toda la Red)
# ==============================================================================

# 1. Extraemos los nodos y aristas como tablas independientes de forma limpia
df_nodos <- grafo |> 
  activate(nodes) |> 
  as_tibble() |> 
  mutate(id_nodo = row_number()) # Guardamos la posición original de cada producto

df_aristas <- grafo |> 
  activate(edges) |> 
  as_tibble()

# Como tu grafo NO es dirigido, un enlace conecta de 'from' a 'to' y viceversa.
# Duplicamos las filas invirtiendo los ejes para capturar TODOS los vecinos de cada producto.
aristas_bidireccionales <- bind_rows(
  df_aristas |> select(nodo_origen = from, nodo_destino = to, weight),
  df_aristas |> select(nodo_origen = to, nodo_destino = from, weight)
)

# 2. PEGAR LAS CATEGORÍAS: Averiguamos la categoría artificial de cada nodo destino (vecino)
aristas_con_categoria <- aristas_bidireccionales |>
  inner_join(
    df_nodos |> select(id_nodo, Categoria_Vecino = Categoria),
    by = c("nodo_destino" = "id_nodo")
  )

# 3. LA VOTACIÓN: Agrupamos por producto origen y sumamos los pesos ('weight') de sus vecinos
votacion_ponderada <- aristas_con_categoria |>
  group_by(nodo_origen, Categoria_Vecino) |>
  summarise(Puntos_Totales = sum(weight), .groups = "drop")

# 4. EL GANADOR: Para cada producto origen, nos quedamos SOLO con la categoría más votada
predicciones_finales <- votacion_ponderada |>
  group_by(nodo_origen) |>
  # slice_max selecciona la fila con el máximo de puntos. 
  # Si hubiera un empate absoluto en puntos, 'with_ties = FALSE' elige uno para no duplicar filas.
  slice_max(order_by = Puntos_Totales, n = 1, with_ties = FALSE) |>
  ungroup() |>
  select(id_nodo = nodo_origen, Prediccion_Homofilia = Categoria_Vecino)

# 5. ACTUALIZAR EL GRAFO: Unimos las predicciones con nuestra lista de nodos original
df_nodos_actualizado <- df_nodos |>
  left_join(predicciones_finales, by = "id_nodo") |>
  # Si algún producto hubiera quedado aislado sin vecinos, le ponemos una etiqueta de control
  mutate(Prediccion_Homofilia = if_else(is.na(Prediccion_Homofilia), "Sin_Vecinos", Prediccion_Homofilia)) |>
  arrange(id_nodo) # Nos aseguramos de mantener el orden exacto de las filas

# Inyectamos la nueva columna de predicción de vuelta en los nodos de tu grafo
grafo <- grafo |>
  activate(nodes) |>
  mutate(Prediccion_Homofilia = df_nodos_actualizado$Prediccion_Homofilia)

# ==============================================================================
# AUDITORÍA DEL MODELO: Evaluación de Resultados
# ==============================================================================

# Filtramos los productos que sí tienen vecinos para hacer un análisis justo
datos_auditoria <- grafo |> 
  activate(nodes) |> 
  as_tibble() |> 
  filter(Prediccion_Homofilia != "Sin_Vecinos")

# Generamos la Matriz de Confusión (Tabla cruzada Realidad vs Predicción)
matriz_confusion <- table(
 Real = datos_auditoria$Categoria,
 Prediccion = datos_auditoria$Prediccion_Homofilia
)

# Calculamos el porcentaje global de acierto (Accuracy)
accuracy_global <- sum(diag(matriz_confusion)) / sum(matriz_confusion) * 100

# Mostramos los resultados en la consola de Quarto
print("--- MATRIZ DE CONFUSIÓN (HOMOFILIA PONDERADA) ---")
print(matriz_confusion)
