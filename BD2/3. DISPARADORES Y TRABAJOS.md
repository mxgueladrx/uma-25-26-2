## Trigger
Bloque PL/SQL que se ejecuta de forma implícita. No admite argumentos. No permite órdenes de `COMMIT`, `ROLLBACK` o `SAVEPOINT`.

```plsql
CREATE [OR REPLACE] TRIGGER nombre 
{BEFORE|AFTER} suceso_disparo ON tabla
[FOR EACH ROW [WHEN condicion_disparo]]
BEGIN
	... -- bloque del trigger
END;

-- suceso_disparo es la operacion DML (insert, delete o update) sobre tabla

DROP TRIGGER nombre;

-- habilitar o deshabilitar trigger
ALTER TRIGGER nombre {ENABLE | DISABLE};
```

## Tipos de triggers
- **Orden, suceso u operación DML**: insert, delete o update.
- **Temporización**: before o after.
- **Nivel**: orden (una vez por consulta) o fila (una vez por registro afectado).

- **Before**: Para controlar o comprobar. El trigger se ejecuta antes de que se produzcan las operaciones DML.
- **After**: Para guardar información. El trigger se ejecuta después de que se haya ejecutado las operaciones DML.

## Orden de ejecución de triggers
1. Before, a nivel de orden.
2. Para cada fila.
	1. Before, a nivel de fila.
	2. Propia orden.
	3. After, a nivel de fila.
3. After, a nivel de orden.
4. Comprobar restricciones.

## Triggers a nivel de fila
Se ejecuta una vez por cada fila procesada por la orden DML disparada. Se usan dos pseudo-registros.

|            | :old           | :new        |
| ---------- | -------------- | ----------- |
| **Insert** | null           | valor nuevo |
| **Update** | valor original | valor nuevo |
| **Delete** | valor original | null        |

`FOR EACH ROW WHEN condicion`: El cuerpo del trigger se ejecuta solo para las filas que cumplan la condición.

```plsql
-- Si el Precio>200, redondearlos a un decimal: 
CREATE OR REPLACE TRIGGER Redondea_Precios_Grandes 
BEFORE INSERT OR UPDATE OF Precio ON Pieza 
FOR EACH ROW WHEN (new.Precio > 200) 
BEGIN 
	:new.Precio := ROUND(:new.Precio,1); 
END Redondea_Precios_Grandes;
```

Para saber la operación causante del trigger: Predicados booleanos `INSERTING`, `UPDATING` y `DELETING`.

```plsql
CREATE OR REPLACE TRIGGER Control_Empleados 
AFTER INSERT OR DELETE OR UPDATE ON Empleados 
BEGIN 
	IF INSERTING THEN 
		INSERT INTO Ctrl_Empleados (Tabla,Usuario,Fecha,Oper) 
		VALUES ('Empleados', USER, SYSDATE,'INSERT'); 
	ELSIF DELETING THEN 
		INSERT INTO Ctrl_Empleados (Tabla,Usuario,Fecha,Oper) 
		VALUES ('Empleados', USER, SYSDATE,'DELETE'); 
	ELSE 
		INSERT INTO Ctrl_Empleados (Tabla,Usuario,Fecha,Oper) 
		VALUES ('Empleados', USER, SYSDATE,'UPDATE'); 
	END IF; 
END Control_Empleados;
```

## Triggers de sustitución
Se ejecuta en lugar de la orden DML. Se define sobre vistas y tener nivel de filas. Se declara usando `INSTEAD OF`.

```plsql
CREATE OR REPLACE TRIGGER Borrar_en_Totales_por_Suministro 
INSTEAD OF DELETE ON Totales_por_Suministrador 
FOR EACH ROW 
BEGIN 
	DELETE FROM Suministradores WHERE Nombre = :old.Suministrador; 
END Borrar_en_Totales_por_Suministro;
```

## Tablas mutantes
- Está modificándose actualmente por una orden DML.
- Siendo leída por Oracle para forzar el cumplimiento de una restricción de integridad referencial.
- Siendo actualizada por Oracle para cumplir una restricción con `ON DELETE CASCADE`.

## Jobs
Son programas planificados. Tareas programadas que se ejecutan automáticamente en un momento específico o en intervalos regulares.

## Ejecución de jobs
Al ejecutarse:
- Se recoge metadatos, argumentos de programa, información de privilegios.
- Se crea una sesión, se comienza la transacción y se ejecuta el job.
- Se hace commit y se cierra la sesión.

Al terminar la ejecución:
- Se planifica la siguiente ejecución si es necesario.
- Se modifica la tabla de trabajos (nueva entrada en el log de trabajos).

```plsql
BEGIN DBMS_SCHEDULER.CREATE_JOB ( 
	job_name => 'mi_tarea', 
	job_type => 'PLSQL_BLOCK', 
	job_action => 'BEGIN insert into prueba values (17,USER,sysdate); END;', 
	start_date => SYSDATE+1, 
	repeat_interval => 'FREQ=SECONDLY;INTERVAL=10', 
	end_date => '30/MAY/2018 20.00.00', 
	enabled => TRUE, 
	comments => 'Inserta una tupla cada 10 segundos a partir de mañana y hasta el 30 de mayo de 2018'
); 
END;

-- ver los trabajos
SELECT * FROM USER_SCHEDULER_JOBS;
-- Borrar un trabajo (o varios)
DBMS_SCHEDULER.DROP_JOB('job1, job2, job3');
-- Parar un trabajo (no su planificación)
DBMS_SCHEDULER.STOP_JOB('job1, job2, job3');
-- Deshabilitarlo
DBMS_SCHEDULER.DISABLE('job1, job2, job3');
--Habilitarlo
DBMS_SCHEDULER.ENABLE('job1, job2, job3');
```
