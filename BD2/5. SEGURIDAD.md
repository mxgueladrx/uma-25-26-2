## Introducción
- **Autenticación**: demostrar que alguien es quien dice ser.
- **Autorización y acceso**: protege los recursos. Solo pueden acceder aquellos que tienen permiso.
- **Auditoría**: capturar quien accede a qué, validando las políticas de seguridad impuestas.

## Gestión de usuarios
En el SO, autenticarse en la BD usando credenciales del SO en lugar de las de Oracle. En Oracle, se necesita un usuario y modo de identificación. 

**Perfil de usuario**: objetos de la BD que establecen limites en los recursos usados por el usuario.
**Rol**: privilegios y permisos agrupados que se asignan a usuarios.

```plsql
CREATE PROFILE Perfil_1 LIMIT 
SESSIONS_PER_USER 3 -- Máximo núm. de sesiones para ese usuario. 
CONNECT_TIME UNLIMITED -- Duración máxima de la conexión. 
IDLE_TIME 10 -- Minutos de tiempo muerto en una sesión. 
FAILED_LOGIN_ATTEMPTS 4 -- nº máximo de intentos para bloquear cuenta. 
PASSWORD_LIFE_TIME 90 -- Nº de días de expiración de la password. 
PASSWORD_GRACE_TIME 3; -- Periodo de gracia después de los 90 días.
```

## Tablespaces
División lógica de los datos de una BD. Cada usuario tiene una por defecto y se puede cambiar.

```plsql
SELECT * FROM DBA_TABLESPACES; -- Comprueba los ts existentes 
CREATE TABLESPACE nombre DATAFILE 'nombrefichero.dbf' SIZE 10M AUTOEXTEND ON; /* Crea un ts con un fichero de tamaño 10M autoextensible. Para que un usuario pueda usarlo debe asignársele una quota de uso */
```

- **Crear usuario**: recién creado no tiene privilegios. Hay tres tipos de usuarios:
	- **Administradores**: SYS y SYSTEM.
	- **Generales**: usuarios creados por admins.
	- **Internos**: usados por procesos externos y en segundo plano de Oracle.

```plsql
CREATE USER Pepe IDENTIFIED BY Clave_Pepe 
TEMPORARY TABLESPACE temp_ts -- Tablespace para los seg. temporales. 
DEFAULT TABLESPACE data_ts -- Tabl. por defecto para sus objetos. 
QUOTA 100M ON test_ts -- Máximo espacio en ese Tablespace. 
QUOTA 500K ON data_ts 
PROFILE Perfil_1; -- Asigna el Perfil_1 al usuario.

-- modificar usuario
ALTER USER pepe ...;
-- borrar usuario
DROP USER pepe CASCADEM
```

- **Crear rol**: se crea vacío y liego se le asignan privilegios o roles. Hay roles que necesitan contraseña.

```plsql
CREATE ROLE nombre_role 
[NOT IDENTIFIED | 
IDENTIFIED {BY password | 
	USING [schema.]package | 
	EXTERNALLY | 
	GLOBALLY}];

-- para poder utilizar un rol identificado por contraseña
SET role nombre_role identified by password

CREATE ROLE Gestor IDENTIFIED BY 123; 
CREATE ROLE USUARIO_NORMAL;
```

## Permisos
**Política Least Privileges**: cuantos menos privilegios mejor.

Permisos grant (conceder) y revoke (revocar). Estos permisos los puede ordenar los propietarios de los objetos, el DBA o los usuarios con privilegio `GRANTABLE`. Hay que especificar el tipo de permiso (`SELECT`, `INSERT`, `DELETE`, `UPDATE`, `ALTER`, `INDEX`, `REFERENCES`, `EXECUTE` y `ALL`) y el objeto (tabla, vista, función, procedimiento...).

**Permisos del sistema**: no se definen para un objeto concreto.

```plsql
GRANT lista_permisos [ON objeto] TO lista_usuarios_o_roles [WITH {GRANT | ADMIN} OPTION];
-- grant opcion da al usuario privilegio para hacer grant a otros

REVOKE lista_permisos [ON objeto] FROM usuario_o_rol;

GRANT CONNECT, Rol_Programador TO Araujo;
GRANT CREATE USER, ALTER USER, DROP USER TO Nous, Zeus WITH ADMIN OPTION;
GRANT CREATE ANY PROCEDURE, CREATE TRIGGERS TO Apolonio;
GRANT ALL ON Empleados TO Casandra WITH GRANT OPTION;
GRANT SELECT ON Empleados TO PUBLIC; 
GRANT REFERENCES (DNI), UPDATE (Salario, Cta_Banco) ON Empleados TO Rol_Nominas; 
REVOKE CREATE SESSION FROM Usuario1, Usuario2;

create role pruebarole identified by 123; 
grant select on mitabla to pruebarole; 
grant pruebarole to unalumno;

Select * from ESC.mitabla; -- ORA-00942: la tabla o vista no existe 00942. 00000 - "table or view does not exist" UNALUMNO: 

set role pruebarole identified by 123; 
Select * from ESC.mitabla;

-- Roles que nos han asignado
SELECT * FROM USER_ROLE_PRIVS;
-- Privilegios de sistema que tiene un roles
SELECT * FROM role_sys_privs;
-- Privilegios de objeto de un roles
SELECT * FROM role_tab_privs;
```

## Vistas
Tabla virtual cuyas filas derivan de otras tablas. Las files no se almacenan, se calculan a paritr de las tablas que dependa.

```plsql
CREATE [OR REPLACE] [[NO] FORCE] VIEW nombre [(atributos)] AS (consulta) [WITH READ ONLY];

CREATE OR REPLACE VIEW SumiNombres AS (SELECT NombreS, NombreP FROM Suministros SP, Suministrador S,Pieza P WHERE SP.S#=S.S# AND SP.P#=P.P#);

CREATE OR REPLACE VIEW Cantidad (NombreS,NumPiezas) AS (SELECT NombreS, COUNT(*) FROM Suministros SP, Suministrador S WHERE SP.P#=S.P# GROUP BY NombreS);
```

La vista siempre está actualizada. Una `CREATE MATERIALIZED VIEW` no se actualiza (foto).

Se puede escribir sobre una vista si es sobre una sola tabla, sin funciones de agregación y todos los campos not null.

Es útil para:
- Seguridad: se restringe el acceso a ciertas filas o columnas.
- Esconde la complejidad de datos.
- Presentar datos de otra forma.
- Aplicaciones independientes a cambios en la tabla base.
- Hacer consultas que no se pueden hacer sin vistas.

## Sinónimos
Nombre alternativo de una tabla, vista, procedimiento... Es seguro porque oculta el nombre y propietario del objeto.
- **Sinónimo público**: el propietario es el grupo de usuarios "public" y todos pueden acceder a él.
- **Sinónimo privado**: pertenece al subesquema de un usuario que puede controlar el uso del mismo.

```plsql
-- por defecto es privado
CREATE [PUBLIC] SYNONYM nombre FOR objeto;

CREATE SYNONYM pventa FOR Paco.Proyect_Venta; -- Crea un sinónimo privado para una tabla del esquema de Paco.
CREATE PUBLIC SYNONYM Prod FOR Scott.Prod@Ventas; -- Crea un sinónimo público para una tabla de Scott en una BD remota llamada Ventas (DBLINK).
```

## Vistas materializadas
Almacenan resultados de una consulta lenta. Accede rápido a los datos, a diferencia de una consulta en tiempo real. Se actualizan periódicamente. Se necesita permiso de `CREATE TABLE` y `CREATE MATERIALIZED VIEW`, acceso a las tablas base y espacio suficiente en el tablespace.

```plsql
CREATE MATERIALIZED VIEW nombre clausulas AS consulta;
```

Las clausulas pueden ser:
- `BUILD [IMMEDIATE | DEFERRED]`: se llena ahora o cuando se haga `REFRESH`.
- `[REFRESH opciones | NEVER REFRESH]`: permite si se actualiza o no los datos. Las opciones son `FAST`, `COMPLETE`, `FORCE`, `ON [COMMIT | DEMAN]`, `START WITH fecha`, `NEXT fecha`.

```plsql
-- Usa dos tablas del esquema Ventas en una BD remota
CREATE MATERIALIZED VIEW Ventas.Clientes_Recientes AS SELECT * FROM Ventas.Clientes@dbs1.uma.es C WHERE EXISTS (SELECT * FROM Ventas.Ordenes@dbs1.uma.es O WHERE C.DNI = O.DNI_Cliente);
-- Cada 7 días, a partir de hoy obtengo la unión de 2 tablas de sendos usuarios en BD remotas
CREATE MATERIALIZED VIEW sales_emp TABLESPACE Mi_Tablespace REFRESH FAST START WITH SYSDATE NEXT SYSDATE + 7 AS SELECT * FROM Patricia.Cosas@Granada UNION SELECT * FROM Miriam.Cosas@Malaga;
```

## Seguridad avanzada
Encriptación a medida: paquete `DBMS_CRYPTO`. `.encrypt`, `.decrypt`, generar claves.

**TDE (Encriptación Transparente de Datos)**: se pueden encriptar columnas o tablespaces enteros. Útil para datos sensibles y solo afecta a como se almacenan los datos.

```plsql
CREATE TABLE nombre (
	col1 tipo encrypt [algoritmo] [nomac] [nosalt],
	...
)

CREATE TABLE employee ( 
	first_name VARCHAR2(128), 
	last_name VARCHAR2(128), 
	empID NUMBER, 
	salary NUMBER(6) ENCRYPT); -- AES 192 bits, MAC y salt (por defecto)
```

**Oracle Virtual Private Database**: restringe el acceso a nivel de fila y columna introduciendo un `WHERE` a las sentencias de forma automática con una función.

```plsql
GRANT EXECUTE ON DBMS_RLS TO usuario; -- necesita este permiso

begin 
dbms_rls.add_policy (
object_schema =>'USUARIO', 
object_name =>'DEPARTAMENTOS', 
policy_name =>'POL_DEPTO_30', 
function_schema =>'USUARIO', 
policy_function => 'SOLO_DEPTO_30', 
statement_types => 'SELECT, UPDATE, DELETE' 
); 
end;

-- Se Activar o desactivar una política: 
begin 
DBMS_RLS.ENABLE_POLICY ( object_schema=>'el_nombre_del_esquema_en_el_que_está_la_tabla', object_name=>'el_nombre_de_tu_tabla', 
policy_name=>'nombre_politica', 
enable=>false
); 
end;
-- Para borrar una política: 
begin 
dbms_rls.drop_policy ( 
object_schema=>'el_esquema', 
object_name=>'la_tabla', 
policy_name=>'el_nombre_de_la_politica' 
); 
end;
```

- **Oracle Label Security**: protegen las tablas a nivel de fila asignando etiquetas. Asigna a los usuarios las etiquetas que tienen acceso.
- Oracle DB Vault: restringe el acceso a los datos incluso a los admins. SYSTEM y SYS no pueden crear usuarios, habrá un account manager y un DB Vault Owner.

## SQL Inyection
Concatenar cadenas en SQL compromete los datos. Vulnerabilidad que permite a un atacante interferir con las consultas de la base de datos.

```plsql
-- ROBO DE DATOS 
-- Paso 1: La consulta prevista Código Vulnerable 
query := SELECT value FROM secret_records 
WHERE user_name='''||vuser||''' AND service_type=vservice || ''''; 
-- Entrada del usuario
vuser = 'Andy' 
vservice = 'Waiter' 
-- Consulta resultante 
SELECT value FROM secret_records 
WHERE user_name= 'Andy' AND service_type='Waiter'; 

-- Paso 2: La inyección maliciosa Entrada del Atacante
vuser = 'Anybody'' OR 1=1 --' 
vservice='Anything' 
-- Consulta Resultante
SELECT value FROM secret_records 
WHERE user_name= 'Anybody’ OR 1=1 --' AND service_type='Anything';

-- La consulta se altera mediante el comentario -- y una condición OR siempre verdadera, permitiendo ver datos restringidos

-- DESTRUCCION DE DATOS 
-- Código Vulnerable 
sentencia := 'begin update productos set precio = precio *1.1 WHERE NOMBRE ='''|| p_nombre||'''; END;';'';
-- La inyección maliciosa 
P_NOMBRE := 'zzzz'' ;DELETE FROM productos WHERE ''a''=''a'; 
-- Código Generado 
begin 
update productos set precio = precio *1.1 WHERE NOMBRE ='zzzz';
DELETE FROM productos WHERE 'a'='a'; 
END;
```

Hay que separar el código de los datos. Bind variables (`:variable`) lo sustituye en tiempo de ejecución.

```plsql
-- Código Seguro (Con Bind Variables) 
query := SELECT value FROM secret_records WHERE user_name= :a AND service_type= :b; 
EXECUTE IMMEDIATE query INTO rec USING vuser, vservice; 
-- El intento de inyección Entrada del Atacante
vuser := 'Anybody'' OR 1=1 --' 
vservice :='Anything'
-- ¿Qué sucede ahora? La base de datos no interpreta caracteres especiales. Busca literalmente 
user_name = ''Anybody' OR service_type='Merger'--'‘’;
```
